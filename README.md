# Axis Energy website

Redesigned marketing site for [Axis Energy](https://www.axis-energyinc.com) — an employee-owned solar EPC and O&M contractor in Holly Springs, NC. Built with [Astro](https://astro.build) as a fully static site: every page is plain HTML/CSS with a few small scripts, so it can be hosted anywhere.

- **Preview (GitHub Pages):** https://rossistance.github.io/Axis-Energy-Modern/
- **Hand-off guide for the web team:** [`docs/HANDOFF.md`](docs/HANDOFF.md)
- **Content review for the Axis team meeting:** [`docs/CONTENT-REVIEW.md`](docs/CONTENT-REVIEW.md)
- **Facts register (where every number comes from):** [`docs/FACTS.md`](docs/FACTS.md)

## Quick start

```bash
nvm use            # Node 22 (see .nvmrc)
npm ci
npm run dev        # http://localhost:4321/Axis-Energy-Modern/
npm run build      # static output in dist/
npm run preview    # serve dist/ locally
npm test           # Playwright: every route, axe accessibility, keyboard nav, forms, layout
```

Copy `.env.example` to `.env` to change the base path, switch preview/production mode, or connect forms, the jobs feed or the LinkedIn news feed.

## What is where

| Path                           | Purpose                                                                                                               |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------------- |
| `src/pages/`                   | One file per route. Dynamic routes: `project/[slug]`, `team/[slug]`.                                                  |
| `src/content/`                 | Editable content: `projects/`, `team/`, `posts/`, `jobs/` (Markdown with front matter).                               |
| `src/data/`                    | Structured copy: company facts, navigation, services, pillars, values, stats, rankings, heritage, form field schemas. |
| `src/components/`              | Header, footer, hero, cards, forms, jobs feed, map, etc.                                                              |
| `src/layouts/BaseLayout.astro` | HTML shell: fonts, SEO tags, header, footer, CTA band, reveal animation.                                              |
| `src/styles/`                  | Design tokens (`tokens.css`), base styles, motion, forms.                                                             |
| `src/assets/`                  | Logos, project and team photos; header photos are listed in `src/data/heroes.ts`.                                     |
| `public/`                      | Icons, manifest, Open Graph image (generated by `scripts/`).                                                          |
| `hosting/`                     | Redirect files for legacy WordPress URLs on Netlify, Vercel, Apache, nginx.                                           |
| `tests/`                       | Playwright suites.                                                                                                    |
| `designs/`                     | Earlier concept explorations (archive).                                                                               |

## Editing content

**Company facts** (address, email, fax, hours, LinkedIn, states served): `src/data/company.ts`. No phone number is published: the one on the old website is Josh Butler's cell (owner, 2026-10-01); add a main office line there if Axis wants one listed. Used by the header, footer, CTA band, contact page and structured data.

**Add a project:** create `src/content/projects/<slug>.md`:

```yaml
---
title: 'Hertford Solar'
city: 'Ahoskie'
state: NC
sizeMwdc: 13.974
year: 2021
commissioned: '2021-12-22' # or "2021-12" or "2021"
type: utility # utility | commercial | municipal | carport | microgrid | community | rooftop
market: 'co-ops-utilities' # optional; section of the Markets page: commercial-industrial | co-ops-utilities | investor-owned | municipal-institutional | developers-ipps
role: ['EPC']
storageMwh: 5.0 # optional
storageBrand: 'Tesla' # optional
partners: ['Client name'] # optional; only with the client's written permission
summary: 'One sentence used on cards and as the meta description.'
image: ../../assets/projects/hertford.jpg # optional, 4:3 or wider
imageAlt: 'Describe the photo'
imageFocus: '35% 50%' # optional; part of the photo kept when it is cropped (CSS object-position)
coordinates: { lat: 36.29, lon: -76.98 } # town centre; places the pin on the home page map
featured: true # show on the home page
published: true # false keeps it out of the site entirely
source: 'Where this information came from'
# Optional case-study detail; each part renders only when present.
impact: 'The outcome, shown in the Impact callout.'
challenge: 'What made the project hard.' # "Project delivery" cards,
approach: 'How Axis solved it.' #          together with challenge
scope: ['Axis scope item', 'Another item'] # sidebar checklist
benefits: # "Why it matters to owners" checklist
  - title: 'Operational proof'
    body: 'One sentence.'
gallery: # extra photos in the sidebar
  - image: ../../assets/projects/hertford-inverters.jpg
    alt: 'Describe the photo'
    caption: 'Optional caption'
---
Narrative paragraphs in Markdown, written like the other project pages.
```

Thirty-two completed projects from the Solar Power World submissions are already entered with `published: false`. Flip the flag once a client name may be shown publicly.

Every published project is shown **without client or partner names, at the owner's request**: the three pages from the owner's 2026 project abstracts (Cooperative Solar and Storage Portfolio, Walnut Grove Microgrid, Wendell Campus Microgrid) and the five earlier case studies (North Carolina Utility-Scale Portfolio, Durham Manufacturing Solar, Charleston Rooftop Solar, Floyd Road, Florence Solar Array). Keep client names out of titles, copy, alt text, captions, slugs, image file names and `partners` until the client grants permission in writing. The three case studies carried over from the old website have new slugs, and their old WordPress URLs are deliberately not redirected: a redirect would put the client's name back in a URL and tie it to the page. If a name is added later and the slug changes, add a redirect from the old URL.

**Team members:** `src/content/team/*.md` (name, title, email, LinkedIn, photo, summary, education, credentials, order); they appear on Leadership (`/about/leadership/`). **Jobs (manual listings):** `src/content/jobs/*.md`; entries with `sample: true` only appear in preview builds.

**News** is the Axis Energy LinkedIn page: each card shows a post's photo, its headline or opening lines and the date, and opens the post on LinkedIn. Only posts the page publishes itself appear; reposts and posts that merely tag Axis are left out. With `NEWS_SOURCE=linkedin` the build reads the latest posts from LinkedIn (setup in `docs/HANDOFF.md`, “LinkedIn news feed”); until then, or if LinkedIn cannot be reached, the page uses `src/content/posts/*.md` (url, date, optional title, summary, image), which can also be kept by hand. Entries with `sample: true` only appear in preview builds. The 2018 articles were retired on 2026-10-01; they remain in the git history.

**Paths that moved** (Leadership, the two Work with Axis forms) are listed in `src/data/routes.ts`; link through it rather than typing paths.

**Services, pillars, values, stats, rankings, heritage timeline:** `src/data/services.ts`, `src/data/pillars.ts`, `src/data/stats.ts`. Each stat carries a `source` and a `confirmed` flag; only confirmed stats render. The six Why Axis cards (`pillars`) are blank placeholders until Axis supplies their copy: a card shows once it has a `title` and `body`, and production builds leave out cards without them. The four service pages (`servicePages`) and the O&M and technical services offerings (`omOfferings`) are defined in `src/data/services.ts`; the Services menu, the footer and the pages under `/services/` are built from them, so adding an offering there adds its page and menu entry.

**Home page map:** state shapes come from `src/data/us-map.ts`, generated by `node scripts/make-us-map.mjs` from the public-domain U.S. Census boundaries in `us-atlas`. The O&M states are `omStates` in `src/data/company.ts`; every other lower-48 state shows as the project footprint. Each project with `coordinates` adds an unlabelled pin at its town, including unpublished projects; projects that share a town share a pin.

**Forms:** field lists for Contact, Developer/Project Owner (the project request) and Subcontractor prequalification live in `src/data/forms/`. Add, remove or reorder fields there; the UI, validation and review step follow automatically.

## Preview vs production

`PUBLIC_SITE_MODE=preview` (default) shows the yellow review ribbon, badges sample jobs, keeps `robots.txt` set to `Disallow: /`, and runs forms in **review mode** (no delivery service connected; submitting composes an email draft instead of claiming success). Set `PUBLIC_SITE_MODE=production` for launch.

## Forms

Each form posts JSON to the endpoint in its environment variable (`PUBLIC_FORM_ENDPOINT_CONTACT`, `_RFQ`, `_SUBS`). The payload shape is compatible with Formspree, Basin, Getform, Web3Forms and similar services, or any small serverless function. With no endpoint configured the form stays in review mode. Spam controls: honeypot field, minimum time-to-submit, and whatever the endpoint provides. Drafts are saved in the visitor's browser (`localStorage`) until submitted.

## Jobs feed

`JOBS_SOURCE=static` (default) reads `src/content/jobs/`. Set it to `greenhouse`, `lever`, `workable` or `bamboohr` with `JOBS_BOARD=<board token / subdomain>`, or to `json-url` with `JOBS_URL=<feed>` for any other applicant-tracking system. Listings are fetched at build time; the GitHub Actions workflow rebuilds every six hours so they stay current. LinkedIn and Indeed do not offer public feeds of a company's openings, so the Careers page links to those boards (`PUBLIC_JOBS_LINKEDIN_URL`, `PUBLIC_JOBS_INDEED_URL`) and lists roles from the ATS.

## Images

The home page headline is the owner's diagram (`src/components/PartnershipDiagram.astro`, 2026-10-01): The Power of Partnership, Solar | Battery Storage | Microgrids | Asset Management (plain labels for now), Performance built for, and the four markets linking to their sections of the Markets page; its curved branches are SVG paths whose coordinates come from the sizes at the top of that file (x in percent, y in rem), so the cards can be renamed in `src/data/project-markets.ts` (`shortTitle`) without redrawing anything; change a size there and the curves follow. Beside it, the hero is a carousel of project photos rather than an illustration. It takes the photo of every published project in project order (`order`), up to six, but only photos at least 1000 px wide, so the large frame never shows a soft, enlarged image; when the original of a smaller photo replaces it (same file name), that project joins the carousel automatically. Each slide links to its project page. The slideshow plays on its own and pauses while the pointer is over it or keyboard focus is inside it; each photo pans and zooms slowly (Ken Burns, four alternating directions in `src/components/HeroCarousel.astro`). There is no visible pause button at the owner's request; a keyboard-only Pause button appears when tabbed to. Set `imageFocus` on a project to choose which part of a wide photo stays in the 3:2 crop.

Every other page except the project pages has the same compact header (`src/components/PageHero.astro`): breadcrumbs, title and one short lead over a full-width photo, the same height on every page. Project pages (`src/pages/project/[slug].astro`) open on a plain title band and an overview of key figures, narrative, details and scope beside the photo, so the photo seen on the project card is not repeated as the header. Keep header leads to a sentence or two; longer copy, buttons and facts go in the page body. The header photos are listed per page in `src/data/heroes.ts`. Today they are placeholders (three 2026 project photos), which the preview labels "Placeholder photo". To set a page's final photo, add it under `src/assets/heroes/` (2400 px wide or more, landscape, with the left side calm enough for the title), point that page's entry at it and set `placeholder: false`. The 2025 hero illustrations were retired on 2026-10-01 at the owner's request; they remain in the git history (`c4bf369`, `src/assets/hero/`). Astro's image service converts every photo to AVIF/WebP at several widths at build time; never commit resized copies.

**Projects page:** published projects are grouped by `type`, in `order`, on compact cards (`src/components/ProjectCard.astro`: photo, title, location, key figures). Small groups share a row of four (`src/components/ProjectTypeGroups.astro` orders the groups to fill the rows). Each service page's "See projects" button opens `/projects/<service>/`, the same page focused on that service's projects (the rules are `projectsForService` in `src/lib/projects.ts`).

**Markets page** (`/markets/`): one section per market, from `src/data/project-markets.ts`; the Markets menu and the home page diagram jump to them, and a project appears in a market through its `market` field. Old links to a market on the Projects page forward to the Markets page.

Project photos in `src/assets/projects/` are the only photography on the site and every one shows a named Axis project: the three images from the old website (392 px wide), three crops from the 2018 brochure (about 660 px wide; the second Charleston rooftop crop is not used on the site) and three photos from the 2026 project abstracts (1275 px wide, cropped to remove the client names printed on the abstract artwork). They are displayed at or below their native size. Replace them with the original high-resolution photographs before launch, keeping the same file names, and add photos for any project you publish from the unpublished list.

Icons and the social sharing image are generated: `npm run icons` and `node scripts/make-og.mjs`.

npm run build && npm run validate:html

## Deployment

Pushes to `Main-Backup` build and deploy to GitHub Pages through `.github/workflows/deploy.yml` (repository **Settings → Pages → Source: GitHub Actions** must be selected once). The same workflow also uploads a root-domain build (`site-dist` artifact) for hosting elsewhere. Full instructions, including custom-domain and DNS cut-over steps, are in [`docs/HANDOFF.md`](docs/HANDOFF.md).

## Source collateral

The marketing source files that informed the redesign (2018 brochures, the 2024 company overview deck, Solar Power World submission workbooks, an O&M requirements memo) were removed from this public repository on 2026-09-27 and handed to the owner as a private archive, because the set also contained an internal job-cost workbook and a payment receipt. The files remain in the repository's git history before that commit; purging them from history requires a history rewrite of every branch and is a separate, deliberate step.
